# AgentShield v0.9 PRD

## 프로젝트 개요

AgentShield는 AI 에이전트의 아웃바운드 네트워크 트래픽을 제어하는 투명 이그레스 방화벽이다.

- GitHub: https://github.com/kamuimk/agentshield
- Language: Rust (edition 2024, MSRV 1.85)
- License: Apache-2.0
- Current: v0.8.0 (292 tests, ~9,200 LOC)

## v0.8 현황

- MITM HTTPS inspection (CONNECT 터널 DLP 스캔)
- CA 관리 CLI (`ca init`, `ca trust`, `ca show`, `ca export`)
- CertCache LRU (per-domain 인증서 동적 생성, max 1000)
- Docker 멀티 플랫폼 이미지 (amd64/arm64) + GitHub Actions workflow
- ProxyMode enum (type-safe transparent/mitm)
- MITM 버퍼 개선: Content-Length 기반 full body 읽기 (10MB cap), streaming relay (`tokio::io::copy`)
- CertCache mutex 최적화 (single lock scope)
- Upstream ClientConfig 캐싱 (per-request → startup 1회 생성)
- Rate limit HTTP 상태코드 429 (이전 403)
- 웹 대시보드 인증 (Bearer token)
- Rate limiting (도메인별 sliding window)
- Policy hot-reload (file watcher + SIGHUP)
- AskBroadcaster (Terminal + Telegram + Web Dashboard)

## v0.9 목표

v0.8의 안정성을 강화하고, Claude Code 네이티브 연동과 감사 로깅(Audit Log)을 추가하며, 대시보드 UX를 개선한다.

1. **v0.8 잔존 이슈 수정** — flaky 테스트, chunked encoding, tilde expansion
2. **Claude Code 네이티브 연동** — `agentshield integrate claude-code` 명령
3. **감사 로깅 (Audit Log)** — Request/Response body 저장 (opt-in)
4. **로그 검색/필터링** — CLI + 웹 대시보드에서 도메인/액션별 필터
5. **대시보드 UX 개선** — 다크/라이트 테마 토글, 시간대별 통계 차트
6. **설정 검증 CLI** — `agentshield config validate` 명령

## 요구사항

### R1: v0.8 잔존 이슈 수정 [P0]

**R1-1: Flaky 테스트 수정 (B1)**

`system_allowlist_bypasses_dlp_for_http` 테스트가 `example.com`에 실제 HTTP 요청을 보내므로 CI에서 간헐 실패한다. 외부 의존을 제거하고 mock 서버를 사용한다.

```rust
// 로컬 mock 서버로 교체
let mock_server = MockServer::start().await;
mock_server.mock(|when, then| {
    when.any_request();
    then.status(200);
});
// proxy 설정에서 mock_server.uri() 사용
```

구현 방법:
1. `tests/proxy_test.rs`에서 `example.com` 대신 로컬 TCP 서버 사용
2. 테스트 내에서 `tokio::net::TcpListener`로 간단한 HTTP 응답 서버 구동
3. 또는 `wiremock` crate 도입 (dev-dependency)

**R1-2: Chunked Transfer-Encoding 지원 (B2)**

MITM 모드에서 `Content-Length` 헤더가 없는 요청(chunked encoding)을 처리한다.

현재 로직: `Content-Length` 파싱 → 해당 바이트만큼 읽기
개선: `Content-Length` 없으면 `Transfer-Encoding: chunked` 확인 → chunk 디코딩 또는 connection close까지 읽기 (안전 상한: 10MB)

```rust
fn read_request_body(headers: &str, stream: &mut TlsStream) -> Result<Vec<u8>> {
    if let Some(len) = parse_content_length(headers) {
        // 기존 로직: 정확히 len 바이트 읽기
    } else if is_chunked(headers) {
        // 새 로직: chunked 디코딩
        decode_chunked(stream, MAX_BODY_SIZE)
    } else {
        // Content-Length도 chunked도 없으면 body 없음으로 처리
        Ok(Vec::new())
    }
}
```

**R1-3: `expand_tilde()` 개선 (B3)**

`dirs` crate를 도입하여 `expand_tilde()`를 안정적으로 구현한다.

```rust
fn expand_tilde(path: &str) -> PathBuf {
    if let Some(rest) = path.strip_prefix("~/") {
        if let Some(home) = dirs::home_dir() {
            return home.join(rest);
        }
    } else if path == "~" {
        if let Some(home) = dirs::home_dir() {
            return home;
        }
    }
    PathBuf::from(path)
}
```

**테스트**: flaky 테스트 안정화, chunked encoding 단위 테스트 3개, expand_tilde 단위 테스트 3개 추가

**예상 소요**: 2시간

### R2: Claude Code 네이티브 연동 [P1]

**배경**: AgentShield의 주요 타겟 중 하나인 Claude Code는 `~/.claude/settings.json`에서 프록시 설정을 관리한다. 수동으로 환경변수를 설정하는 것보다 CLI 명령 하나로 연동할 수 있어야 한다.

**기능 요구사항**:

1. `agentshield integrate claude-code` — Claude Code가 AgentShield를 통해 트래픽을 라우팅하도록 설정
2. `agentshield integrate remove` — 기존 제거 명령이 Claude Code 설정도 정리
3. Claude Code의 설정 파일 경로: `~/.claude/settings.json`
4. 설정 항목:
   - `env.HTTPS_PROXY` → `http://127.0.0.1:18080`
   - `env.HTTP_PROXY` → `http://127.0.0.1:18080`
   - MITM 모드 시: `env.NODE_EXTRA_CA_CERTS` → CA cert 경로
5. Claude Code 미설치 시 안내 메시지 출력

**기술 설계**:

```rust
// src/cli/integrate.rs

fn integrate_claude_code(config: &AppConfig) -> anyhow::Result<()> {
    let settings_path = dirs::home_dir()
        .ok_or_else(|| anyhow::anyhow!("Cannot find home directory"))?
        .join(".claude")
        .join("settings.json");

    if !settings_path.exists() {
        println!("Claude Code settings not found at {:?}", settings_path);
        println!("Is Claude Code installed?");
        return Ok(());
    }

    let content = std::fs::read_to_string(&settings_path)?;
    let mut settings: serde_json::Value = serde_json::from_str(&content)?;

    let proxy_url = format!("http://{}", config.proxy.listen);
    let env = settings
        .as_object_mut()
        .and_then(|o| o.entry("env").or_insert(json!({})).as_object_mut());

    if let Some(env) = env {
        env.insert("HTTPS_PROXY".to_string(), json!(proxy_url));
        env.insert("HTTP_PROXY".to_string(), json!(proxy_url));

        // MITM 모드 시 CA cert 경로 추가
        if config.proxy.mode == ProxyMode::Mitm {
            if let Some(ref ca_dir) = config.proxy.ca_dir {
                let cert_path = expand_tilde(ca_dir).join("cert.pem");
                env.insert("NODE_EXTRA_CA_CERTS".to_string(),
                    json!(cert_path.to_string_lossy()));
            }
        }
    }

    std::fs::write(&settings_path, serde_json::to_string_pretty(&settings)?)?;
    println!("✓ Claude Code configured to use AgentShield proxy at {}", proxy_url);
    Ok(())
}

fn remove_claude_code() -> anyhow::Result<()> {
    let settings_path = dirs::home_dir()
        .ok_or_else(|| anyhow::anyhow!("Cannot find home directory"))?
        .join(".claude")
        .join("settings.json");

    if !settings_path.exists() {
        return Ok(());
    }

    let content = std::fs::read_to_string(&settings_path)?;
    let mut settings: serde_json::Value = serde_json::from_str(&content)?;

    if let Some(env) = settings.as_object_mut().and_then(|o| o.get_mut("env").and_then(|v| v.as_object_mut())) {
        env.remove("HTTPS_PROXY");
        env.remove("HTTP_PROXY");
        env.remove("NODE_EXTRA_CA_CERTS");
    }

    std::fs::write(&settings_path, serde_json::to_string_pretty(&settings)?)?;
    println!("✓ Claude Code proxy configuration removed");
    Ok(())
}
```

### R3: 감사 로깅 (Audit Log) [P1]

**배경**: 보안 감사(audit) 목적으로 프록시를 통과한 HTTP 요청/응답의 body를 선택적으로 기록해야 한다. 기본값은 비활성화(opt-in)이며, 활성화 시 SQLite에 body를 저장한다.

**기능 요구사항**:

1. 설정:
   ```toml
   [logging]
   audit = true                    # body 저장 활성화 (default: false)
   audit_max_body_size = 65536     # body 최대 저장 크기 (default: 64KB)
   audit_actions = ["deny", "ask", "dlp"]  # 기록할 액션 (default: all)
   ```
2. `audit = true` 시 요청 body를 `request_logs` 테이블의 새 `body` 컬럼에 저장
3. body 크기가 `audit_max_body_size` 초과 시 truncation + `[truncated]` 표시
4. MITM 모드에서는 복호화된 요청 body 저장
5. Transparent 모드에서는 HTTP 요청만 body 저장 (HTTPS CONNECT는 불가)
6. `agentshield logs --show-body` 옵션으로 body 포함 출력
7. 웹 대시보드에서 로그 상세 보기 시 body 표시 (접이식 패널)
8. 민감 데이터 body 저장 시 DLP 스캔 결과도 함께 기록

**기술 설계**:

```rust
// src/policy/config.rs
#[derive(Debug, Clone, Deserialize, Serialize, Default)]
pub struct LoggingConfig {
    /// Enable audit logging (request body storage).
    #[serde(default)]
    pub audit: bool,
    /// Maximum body size to store in bytes (default: 65536).
    #[serde(default = "default_audit_max_body_size")]
    pub audit_max_body_size: usize,
    /// Action types to audit. Empty = all actions.
    #[serde(default)]
    pub audit_actions: Vec<String>,
}

fn default_audit_max_body_size() -> usize {
    65536 // 64KB
}
```

```rust
// 마이그레이션
fn migrate_db(conn: &Connection) -> Result<()> {
    // request_body 컬럼 존재 여부 확인
    let has_body_column = conn
        .prepare("PRAGMA table_info(request_logs)")
        .and_then(|mut stmt| {
            stmt.query_map([], |row| row.get::<_, String>(1))
                .map(|rows| rows.flatten().any(|name| name == "request_body"))
        })
        .unwrap_or(false);

    if !has_body_column {
        conn.execute_batch(
            "ALTER TABLE request_logs ADD COLUMN request_body TEXT;
             ALTER TABLE request_logs ADD COLUMN dlp_findings TEXT;"
        )?;
    }
    Ok(())
}
```

### R4: 로그 검색/필터링 [P1]

**배경**: 로그가 축적되면 특정 도메인이나 액션의 로그만 빠르게 찾아야 한다.

**기능 요구사항**:

1. CLI 필터링:
   ```bash
   agentshield logs --domain api.anthropic.com
   agentshield logs --action deny
   agentshield logs --action ask --domain "*.github.com"
   agentshield logs --since "2026-02-18" --until "2026-02-19"
   agentshield logs --search "exfiltrate"   # body 검색 (audit 활성화 시)
   ```
2. 웹 대시보드 필터링:
   - 도메인 필터 입력창
   - 액션별 토글 버튼 (allow/deny/ask/rate-limited/system-allow)
   - 시간 범위 선택기
3. `/api/logs` 쿼리 파라미터:
   ```
   GET /api/logs?domain=api.anthropic.com&action=deny&limit=50&since=2026-02-18T00:00:00
   ```
4. SQLite 인덱스 추가 (domain, action, timestamp)

**기술 설계**:

```rust
// src/logging/mod.rs
pub struct LogFilter {
    pub domain: Option<String>,
    pub action: Option<String>,
    pub since: Option<chrono::NaiveDateTime>,
    pub until: Option<chrono::NaiveDateTime>,
    pub search: Option<String>,
    pub limit: u32,
}

pub fn query_logs_filtered(pool: &DbPool, filter: &LogFilter) -> Result<Vec<RequestLog>> {
    let conn = pool.get()?;
    let mut sql = String::from("SELECT * FROM request_logs WHERE 1=1");
    let mut params: Vec<Box<dyn rusqlite::ToSql>> = Vec::new();

    if let Some(ref domain) = filter.domain {
        sql.push_str(" AND domain LIKE ?");
        params.push(Box::new(format!("%{}%", domain)));
    }
    if let Some(ref action) = filter.action {
        sql.push_str(" AND action = ?");
        params.push(Box::new(action.clone()));
    }
    if let Some(ref since) = filter.since {
        sql.push_str(" AND timestamp >= ?");
        params.push(Box::new(since.to_string()));
    }
    if let Some(ref until) = filter.until {
        sql.push_str(" AND timestamp <= ?");
        params.push(Box::new(until.to_string()));
    }
    if let Some(ref search) = filter.search {
        sql.push_str(" AND (request_body LIKE ? OR domain LIKE ? OR path LIKE ?)");
        let pattern = format!("%{}%", search);
        params.push(Box::new(pattern.clone()));
        params.push(Box::new(pattern.clone()));
        params.push(Box::new(pattern));
    }

    sql.push_str(" ORDER BY id DESC LIMIT ?");
    params.push(Box::new(filter.limit));

    // execute query...
}
```

### R5: 대시보드 UX 개선 [P2]

**배경**: 현재 대시보드는 Tailwind 인라인 CSS로 밝은 테마만 지원한다. 다크 테마와 기본적인 시각화를 추가하여 사용성을 높인다.

**기능 요구사항**:

1. 다크/라이트 테마 토글:
   - 우측 상단 토글 버튼
   - `localStorage`에 선호도 저장
   - 시스템 설정 자동 감지 (`prefers-color-scheme: dark`)
2. 시간대별 요청 통계 차트:
   - 최근 1시간의 분당 요청 수 막대그래프
   - 액션별 색상 구분 (allow=green, deny=red, ask=yellow, rate-limited=orange)
   - Canvas 기반 순수 JS 구현 (외부 라이브러리 없음)
3. 실시간 로그 자동 스크롤 토글:

### R6: 설정 검증 CLI [P2]

**배경**: `agentshield.toml` 수정 후 서버 시작 전에 설정 유효성을 확인할 수 있어야 한다. 현재는 `start` 실행 시에만 파싱 에러를 확인할 수 있다.

**기능 요구사항**:

1. `agentshield config validate [--config path]` — 설정 파일 검증
2. 검증 항목:
   - TOML 파싱 성공
   - 환경변수 치환 (`${VAR}`) 유효성
   - 정책 룰 도메인 형식 검증
   - listen 주소 형식 검증
   - CA 디렉토리 존재 여부 (MITM 모드)
   - DLP 패턴 이름 유효성
   - 룰 이름 중복 검사
3. 검증 결과 출력:
   ```
   ✓ TOML syntax valid
   ✓ Environment variables resolved
   ✓ Policy rules: 5 rules defined
   ✓ Listen address: 127.0.0.1:18080
   ✗ CA directory not found: ~/.agentshield/ca (required for MITM mode)
   ⚠ Rule "catch-all" matches all domains — consider restricting

   Result: 1 error, 1 warning
   ```
4. 종료 코드: 에러 있으면 1, 없으면 0

**기술 설계**:

```rust
// src/cli/mod.rs
#[derive(Subcommand)]
enum ConfigCommand {
    Validate,
}

fn cmd_config_validate(config_path: &Path) -> anyhow::Result<()> {
    let mut errors = Vec::new();
    let mut warnings = Vec::new();

    // 1. TOML 파싱
    match AppConfig::load_from_path(config_path) {
        Ok(config) => {
            println!("✓ TOML syntax valid");
            println!("✓ Environment variables resolved");

            // 2. 정책 룰 검증
            validate_rules(&config.policy, &mut errors, &mut warnings);

            // 3. listen 주소 검증
            validate_listen_address(&config.proxy.listen, &mut errors);

            // 4. MITM CA 디렉토리 검증
            if config.proxy.mode == ProxyMode::Mitm {
                validate_ca_dir(&config.proxy.ca_dir, &mut errors);
            }

            // 5. DLP 패턴 검증
            if let Some(ref dlp) = config.dlp {
                validate_dlp_patterns(dlp, &mut warnings);
            }

            // 6. 룰 이름 중복 검사
            check_duplicate_rule_names(&config.policy.rules, &mut warnings);
        }
        Err(e) => {
            errors.push(format!("Config load failed: {}", e));
        }
    }

    // 결과 출력
    for w in &warnings {
        println!("⚠ {}", w);
    }
    for e in &errors {
        println!("✗ {}", e);
    }

    if errors.is_empty() && warnings.is_empty() {
        println!("\nResult: All checks passed ✓");
    } else {
        println!("\nResult: {} error(s), {} warning(s)", errors.len(), warnings.len());
    }

    if errors.is_empty() { Ok(()) } else { std::process::exit(1) }
}
```

**테스트**:
- 유효한 설정 → 에러 0, 종료 코드 0
- 잘못된 TOML → 에러 1
- 없는 환경변수 → 에러 1
- 중복 룰 이름 → 경고 1
- MITM + CA 디렉토리 없음 → 에러 1
- 와일드카드 catch-all 룰 → 경고 1

**예상 소요**: 1.5시간
