# AgentShield v0.7 PRD

## 프로젝트 개요

AgentShield는 AI 에이전트의 아웃바운드 네트워크 트래픽을 제어하는 투명 이그레스 방화벽이다.

- GitHub: https://github.com/kamuimk/agentshield
- Language: Rust (edition 2024, MSRV 1.85)
- License: Apache-2.0
- Current: v0.6.0 (219 tests, ~8,500 LOC)

## v0.6 현황

- AskResponder trait + AskBroadcaster (다중 응답 채널 추상화)
- TerminalResponder, TelegramResponder (inline keyboard 양방향 승인), WebDashboardResponder
- axum 기반 웹 대시보드 (로그 조회, ASK 승인, 정책 편집, SSE 실시간 스트림)
- 정책 hot-reload (파일 감시 + SIGHUP + API)
- LogEvent broadcast 채널

1. **v0.6 리뷰 이슈 수정** — CI 수정, CDN 제거, 코드 안정성

```rust
// telegram.rs에 추가
fn spawn_cleanup_task(
    pending: Arc<Mutex<HashMap<String, PendingAsk>>>,
    message_ids: Arc<Mutex<HashMap<String, i64>>>,
) {
    tokio::spawn(async move {
        let mut interval = tokio::time::interval(Duration::from_secs(60));
        loop {
            interval.tick().await;
            // pending은 oneshot sender가 drop되면 자동 정리되지만
            // message_ids는 수동 정리 필요
            let mut ids = message_ids.lock().unwrap();
            // 단순 시간 기반 정리를 위해 timestamp 필드 추가 필요
            // 또는 entry 수가 100개를 초과하면 가장 오래된 것부터 제거
            if ids.len() > 100 {
                ids.clear();
                tracing::info!("Cleared stale Telegram message_ids ({} entries)", ids.len());
            }
        }
    });
}
```

더 정교한 방법: `PendingAsk`와 `message_ids` entry에 `Instant` 타임스탬프를 추가하고, 5분 초과 시 개별 제거.

### R2: 웹 대시보드 인증 [P1]

**배경**: v0.6의 웹 대시보드는 `127.0.0.1` 바인딩으로 로컬 전용이지만, 포트 포워딩이나 원격 접속 환경에서는 무방비 상태다. SSH 터널로 접근하는 시나리오도 현실적이므로 인증이 필요하다.

**기능 요구사항**:

1. Bearer token 인증:
   ```toml
   [web]
   enabled = true
   listen = "127.0.0.1:18081"
   auth_token = "${AGENTSHIELD_WEB_TOKEN}"   # 설정 시 인증 활성화
   ```
2. `auth_token`이 미설정이면 인증 없이 동작 (v0.6 하위호환)
3. API 요청에 `Authorization: Bearer <token>` 헤더 필수
4. 대시보드 HTML 접근 (`GET /`)에는 인증 불필요 (HTML 자체에 토큰 입력 UI)
5. 토큰 불일치 시 `401 Unauthorized` + JSON 에러 응답
6. 대시보드 프론트엔드에 토큰 입력 모달:
   - 최초 접근 시 토큰 입력 프롬프트
   - 입력된 토큰을 `sessionStorage`에 저장 (브라우저 탭 닫으면 삭제)
   - 모든 API 요청에 `Authorization` 헤더 자동 추가

**기술 설계**:

```rust
// src/web/mod.rs — axum middleware
async fn auth_middleware(
    State(state): State<Arc<AppState>>,
    req: axum::http::Request<Body>,
    next: axum::middleware::Next,
) -> axum::response::Response {
    // auth_token이 None이면 인증 skip
    let Some(ref expected_token) = state.auth_token else {
        return next.run(req).await;
    };

    // GET / (dashboard HTML)은 인증 제외
    if req.uri().path() == "/" {
        return next.run(req).await;
    }

    // Bearer token 검증
    let auth_header = req.headers().get("authorization").and_then(|v| v.to_str().ok());
    match auth_header {
        Some(header) if header.starts_with("Bearer ") => {
            let token = &header[7..];
            if token == expected_token {
                return next.run(req).await;
            }
        }
        _ => {}
    }

    (StatusCode::UNAUTHORIZED, Json(json!({"error": "invalid or missing token"}))).into_response()
}
```

**테스트**:
- `auth_token` 미설정 → 모든 API 접근 가능
- `auth_token` 설정 + 올바른 Bearer → 200
- `auth_token` 설정 + 잘못된 Bearer → 401
- `auth_token` 설정 + 헤더 없음 → 401
- `GET /` → 인증 없이 200 (HTML 반환)
- SSE 엔드포인트에도 인증 적용

### R3: Rate Limiting [P1]

**배경**: AI 에이전트가 반복적으로 같은 도메인에 요청을 보내는 경우 (예: 무한 루프, 잘못된 재시도 로직) 를 탐지하고 차단해야 한다.

**기능 요구사항**:

1. 도메인별 sliding window rate limit
2. 설정은 정책 룰 단위로 지정:
   ```toml
   [[policy.rules]]
   name = "anthropic"
   domains = ["api.anthropic.com"]
   action = "allow"
   rate_limit = { max_requests = 100, window_secs = 60 }
   ```
3. rate limit 초과 시:
   - 요청 거부 (403 Forbidden)
   - `X-AgentShield-Reason: Rate limit exceeded (100/60s for api.anthropic.com)` 헤더
   - 알림: `NotificationEvent::RateLimited { domain, method, limit, window }`
   - 로그: `action = "rate-limited"`
4. rate limit 미설정 룰은 무제한 (기존 동작 유지)
5. `agentshield status`에서 rate limit 상태 표시
6. 웹 대시보드 `/api/status`에 rate limit 카운터 포함

**기술 설계**:


```rust
// src/ratelimit/mod.rs — 새 모듈
use std::collections::HashMap;
use std::sync::Mutex;
use std::time::Instant;

/// Sliding window rate limiter.
pub struct RateLimiter {
    /// domain → list of request timestamps
    windows: Mutex<HashMap<String, Vec<Instant>>>,
}

impl RateLimiter {
    pub fn new() -> Self {
        Self { windows: Mutex::new(HashMap::new()) }
    }

    /// Check if a request is allowed under the rate limit.
    /// Returns `true` if allowed, `false` if rate limited.
    pub fn check_and_record(
        &self,
        domain: &str,
        max_requests: u64,
        window_secs: u64,
    ) -> bool {
        let now = Instant::now();
        let window = std::time::Duration::from_secs(window_secs);
        let mut map = self.windows.lock().unwrap();
        let timestamps = map.entry(domain.to_string()).or_default();

        // Remove expired timestamps
        timestamps.retain(|t| now.duration_since(*t) < window);

        if timestamps.len() as u64 >= max_requests {
            return false; // rate limited
        }

        timestamps.push(now);
        true
    }

    /// Get current request count for a domain within its window.
    pub fn current_count(&self, domain: &str, window_secs: u64) -> u64 {
        let now = Instant::now();
        let window = std::time::Duration::from_secs(window_secs);
        let map = self.windows.lock().unwrap();
        map.get(domain)
            .map(|ts| ts.iter().filter(|t| now.duration_since(**t) < window).count() as u64)
            .unwrap_or(0)
    }
}
```

- 알림 발송 확인

### R4: CLI `dashboard` 명령 [P2]

**배경**: 웹 대시보드 URL을 기억하기 어렵고, 설정 파일에서 포트를 확인해야 한다.

**기능 요구사항**:

4. 플랫폼별 브라우저 열기: `open` (macOS), `xdg-open` (Linux), `start` (Windows)

**기술 설계**:

```rust
fn cmd_dashboard(config_path: &Path) -> anyhow::Result<()> {
    let config = AppConfig::load_from_path(config_path)?;
    match config.web {
        Some(ref web) if web.enabled => {
            let url = format!("http://{}", web.listen);
            println!("Opening dashboard: {}", url);
            open_browser(&url)?;
        }
        _ => {
            println!("Web dashboard is not enabled.");
            println!("Add [web] enabled = true to your config file.");
        }
    }
    Ok(())
}

fn open_browser(url: &str) -> anyhow::Result<()> {
    #[cfg(target_os = "macos")]
    std::process::Command::new("open").arg(url).spawn()?;
    #[cfg(target_os = "linux")]
    std::process::Command::new("xdg-open").arg(url).spawn()?;
    #[cfg(target_os = "windows")]
    std::process::Command::new("cmd").args(["/C", "start", url]).spawn()?;
    Ok(())
}
```

## TOML 설정 예시 (v0.7)

```toml
[proxy]
listen = "127.0.0.1:18080"
mode = "transparent"

[ask]
timeout = 120

[policy]
default = "deny"
hot_reload = true

[[policy.rules]]
name = "anthropic"
domains = ["api.anthropic.com"]
action = "allow"
rate_limit = { max_requests = 100, window_secs = 60 }

[[policy.rules]]
name = "github-read"
domains = ["*.github.com", "*.githubusercontent.com"]
methods = ["GET"]
action = "allow"

[[policy.rules]]
name = "github-write"
domains = ["*.github.com"]
methods = ["POST", "PUT", "DELETE"]
action = "ask"

[[policy.rules]]
name = "web-browsing"
domains = ["*"]
action = "ask"
rate_limit = { max_requests = 30, window_secs = 60 }

[dlp]
enabled = true

[system]
allowlist = ["api.telegram.org"]

[notification]
enabled = true

[notification.telegram]
bot_token = "${AGENTSHIELD_TELEGRAM_TOKEN}"
chat_id = "${AGENTSHIELD_TELEGRAM_CHAT_ID}"
events = ["deny", "dlp", "ask"]
interactive = true

[web]
enabled = true
listen = "127.0.0.1:18081"
auth_token = "${AGENTSHIELD_WEB_TOKEN}"
```
