# Sensitive request transport observations

The inspected HTTP and HTTPS proxy paths retain a one-shot correlation ticket after sensitive-data approval. When the forwarding operation settles, optional responders receive a metadata-only terminal observation with the original approval request ID and exact held-request SHA256. This never grants another send. The existing loopback connector authenticates `/outcome` requests and replies with challenge-bound, path-separated HMAC; keys, payloads, URL paths and response bodies are not included.

Observation phases are `not_attempted`, `attempted_unknown`, `response_headers`, and `response_complete`. A write attempt is marked before calling the writer: a partial write or an error cannot prove zero bytes left the process. A response status is recorded only after parsing upstream headers. `completed` termination means a complete framed response was observed; it does not prove recipient application processing or delivery to the downstream client. A downstream relay error is reported as `failed` even if the entire upstream response was observed.

The observer accepts bounded HTTP/1 headers and supports Content-Length, no-body HEAD/204/304, close-delimited bodies, and chunked bodies ending with the exact zero-chunk terminal frame. It rejects completion claims for truncation, duplicate/conflicting framing, unsupported transfer encodings, upgrade responses, nonempty trailers, oversized/malformed headers and extra bytes. Response bodies are counted or skipped, not retained. This observer does not change forwarding policy or claim a remote exactly-once side effect.

Reporting is bounded to 2.5 seconds and does not retry the upstream request. Older connectors may refuse the observation without gaining any authority. Cancellation, process death, expiry or unavailable reporting can leave no terminal observation: absence must remain **unknown**, never be inferred as successful delivery or zero transmission. Durable crash/reconnect reporting is not implemented by this change.

Validation includes real loopback approved HTTP requests, exact request-digest correlation and truncated-response controls; signed loopback reporting with wrong-digest rejection; framing tests including chunk boundaries and truncated terminals; and the existing real TLS non-delivery and network-security suites. These synthetic fixtures do not qualify an employee identity, a real human approval, a normally installed distribution or whole-system packet enforcement.
